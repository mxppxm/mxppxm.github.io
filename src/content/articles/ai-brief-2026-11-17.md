## 🏛️ 大厂动作

### A1 · 阿里 Qwen4-Max：2.4 万亿参数，单任务成本砍六成

11 月 16 日阿里发布 Qwen4 系列首款模型 **Qwen4-Max**：2.4 万亿总参数、每 token 激活 71B、原生视觉、100 万 token 上下文。架构是带 Qwen 稀疏注意力（QSA）的新 MoE，官方称每个 token 激活参数比上代少 25%。

最硬的数字不是参数，是成本：官方称平均单任务成本比 Qwen3.8-Max 降 **58%–60%**（智东西口径 58%、IT 之家口径"超 60%"，同一份官方材料的不同算法，别当精确值看）。它开始卖"交付"而不是"回答"——官方交付记录里，单个汽车零件加工程序从人工 475 分钟压到 24 分钟，198 份散乱底稿整理成 86 页尽调报告；一个物理科普网站案例里分 14 次交付可用版本，最后长成带 3D 动画和交互实验的站点。

需要留心眼：这批数字全部来自阿里自测与自建基准（DeepSWE、AA-Briefcase、HLAB-Vals），**第三方复现还没出来**。

> ⚡ 跟你：先交可用首版、按你的意见逐版扩——这正是你写页面的真实节奏。如果它真能接住这种迭代，那它替的不是编辑器，是你来回改稿的那十几轮。

### A2 · OpenAI 的两张牌：1 美元的价格，和 100 亿美元的收入

中端模型 **GPT-6.1 Terra** 的牌价现在是输入 1 美元 / 输出 5 美元每百万 token，缓存读取 0.05 美元，Batch 与 Flex 再打五折。它打的不是刷榜，是"大量重复劳动"：读发票、录进财务系统、跑 computer use。

价格表里藏着一个坑：**输入超过 272K token 后单价翻倍**（2 美元输入 / 7.5 美元输出）。"上下文档位"第一次变成了产品设计问题——长上下文不再是免费炫耀项，是要算钱的。

钱的那一侧同样夸张：彭博称 OpenAI 九月季度营收 100 亿美元；11 月 7 日又完成 110 亿美元融资首批到账，估值 1.25 万亿美元，整轮可能到 200 亿美元。

> ⚡ 跟你：如果你给 agent 塞整份设计稿或整篇长文，272K 这条线就是账单分水岭。把它当硬约束写进代码，别等月底看账单才发现翻倍。

来源：[OpenAI 官方](https://openai.com/index/introducing-gpt-6-1-terra) · [LiteLLM 定价拆解](https://docs.litellm.ai/blog/gpt-6-1-terra) · [WireRead](https://wireread.com/news)

### A5 · Meta 打出一张 0.1 美元的牌：让 agent 干脏活的专用模型

11 月 9 日 Meta 发布 **Muse Ember**，自家最小的模型，0.10 美元/百万输入、0.50 美元/百万输出，200K 以上长请求涨到 0.30 / 1.50。定位明确：不做前台对话，专跑 agent 内部那些一天重复几百次的活——子任务、工具调用、路由、批量读文件和图片。

Meta 的说法是"比 Haiku 和 Luna 更便宜也更聪明（按单任务成本算）"，引用 Artificial Analysis 的成本数据。注意这个"更聪明"是按**单位成本**排的，不是绝对能力。

这条消息真正的含义是：**模型市场正在按 agent 的器官分工**。有负责规划的贵模型，也得有负责跑腿的便宜模型。

> ⚡ 跟你：你那套 agent 流程里最烧钱的往往不是"想"，是"读文件、改名、跑一遍"。这类活换成 0.1 美元的模型，一年省下来的钱够你升级设备。

## 🧪 社区与开源

### B1 · Chrome 团队开源了一个"反过时"技能：让 agent 别再写 2019 年的前端

本周最该你亲自看的一条：**GoogleChrome/modern-web-guidance-src**，一天涨 1,200 星（总量 7.7k，仓库 9 个月前建的）。它做的事很朴素也很狠——通过一个**本地 CLI 技能**，把精选的现代 Web 平台最佳实践注入编码智能体。

为什么重要：所有编码模型的训练数据都有滞后，它们对 CSS 的认知大概率停在你上次吐槽的那一年。于是你会看到 agent 熟练地写一堆 polyfill、flex 老写法、被废弃的 API——语法没错，但那是三年前的正确。这个仓库等于给 agent 装了一份"当前标准"的补丁。

它也是本周一个更大的信号：Agent Skills 已经是浏览器厂商的正式分发渠道了。

> ⚡ 跟你：这条几乎是为你写的。你的 skill 生态里加一个"现代 Web 事实源"，比在 prompt 里反复叮嘱"别用 float 布局"有效得多——把知识放文件里，别放记忆里。

来源：[HotRepo 日榜 11/16](https://hotrepo.ai/zh) · [GitHub](https://github.com/GoogleChrome/modern-web-guidance-src)

### B2 · chrome-devtools-mcp 稳在 5.7 万星：让 agent 自己打开浏览器找 bug

**ChromeDevTools/chrome-devtools-mcp** 一天再涨 837 星，总量 57.7k。它把真实 Chrome 交给编码 agent：打开页面、读 DOM、录性能追踪、看网络请求和控制台报错。

和"截图给模型看"相比这是质的差别。截图只能看到"长得对不对"，DevTools 协议能看到"为什么慢、为什么报错、哪个请求 404 了"。也就是说 agent 第一次具备了**可验证的调试闭环**。

它的持续高热说明一件事：Agent 能力的瓶颈，正在从"会不会写"移到"能不能自己验收"。

> ⚡ 跟你：你一直靠无头截图 + 读图自查，这条路对"渲染对不对"有效、对"为什么卡"无效。接上 DevTools MCP，让 agent 自己读 trace，你的验证环节能从"我看看"变成"它自己证明"。

来源：[HotRepo 日榜](https://hotrepo.ai/zh) · [GitHub](https://github.com/ChromeDevTools/chrome-devtools-mcp)

### B3 · Univer 一天涨 1,878 星登顶：把 Office 变成可嵌入的零件

今日榜首 **dream-num/univer**，+1,878 星，总量 27.7k，四年前建的仓库——典型的"老项目被新需求重新点亮"。它是一套可嵌入的 Office SDK：表格、文档、幻灯片、协作、文件处理，**同时面向人和 AI agent**。

它踩中的需求很具体：当 agent 开始产出"表"和"文档"，你总不能让它在聊天框里吐一个 markdown 表格就完事。用户需要的是能继续编辑、能协作、能导出的真表格。

同一天榜单 18 个项目，绝大多数是 agent 周边的"管道件"。真正的模型项目很少——**这一轮的热度在基础设施，不在模型。**

> ⚡ 跟你：你做创意工具时常卡在"生成完怎么让人接手"。这类可嵌入 SDK 就是交接面：agent 出初稿，人在熟悉的表格/画布里改，而不是在聊天框里复制粘贴。

### B4 · ⚠️ 技能层开始"质检"：评估器、红队包、漏洞技能同时上榜

三条同向信号：**NVIDIA/SkillEvaluator** +953 星（2.6k），做"上线前校验、去重、并实测技能对 agent 行为的影响"；**elementalsouls/Claude-BugHunter** +1,057 星（7.4k），把漏洞挖掘做成 82 个技能 + 15 个斜杠命令 + 681 个已披露报告模式的技能包；**anthropics/skills** 仍是技能类总量最高（194.7k，一周 +6.2k）。

SkillEvaluator 的定位最值得警惕：它假定技能会**互相语义重叠、会悄悄改变 agent 行为**。也就是说社区已经承认了一件事——技能不是插件，技能是**会污染行为的代码**，需要质量门、需要回归测试。

BugHunter 则是另一面：同一套机制，既能帮你写页面，也能帮你找漏洞。机制中立，后果不对称。

> ⚡ 跟你：你的 skill 越攒越多，早晚会遇到"装了新的、旧的行为变了"。抄 SkillEvaluator 的思路：给每个 skill 留一句"什么时候该触发"，跑一遍回归，别靠感觉。

### B5 · 大厂也开始开源"agent 流水线"：LoopForge 与 open-code-review

**Tencent/LoopForge** 三个月大，一天涨 1,016 星（+30%，总量 2.2k）。它做的是自托管的编码智能体交付编排：用可复用 SOP 调度 CodeBuddy、Codex、Claude Code，并内置人工审批关卡。关键词是"自托管"和"审批关卡"。

**alibaba/open-code-review** 已 52.9k 星，一天 +946。路线不是"让 LLM 审代码"，而是**确定性流水线 + LLM Agent 混合**：先跑规则（NPE、线程安全、XSS、SQL 注入），再由 agent 在可疑处判断，输出精确到行的评论。

两条放一起读很有意思：**中国两家大厂，开源的都不是模型，而是"把 agent 管起来的流程"。** 它们默认你已经有一堆 agent，缺的是纪律。

> ⚡ 跟你："确定性流水线 + LLM 判断"这个混合结构比纯 agent 稳得多。你写自动化脚本时也可以这么分层：规则能判的死判，剩下的才交给模型。

## 🔬 研究前沿

### C1 · 书生-S2.1 Flash 开源：让 AI 去"做实验"，不只是"读论文"

上海人工智能实验室联合复旦、北大、中科院软件所等机构发布并开源 **书生-S2.1 Flash（Sage S2.1 Flash）**，主打 AI4AI。在机器学习工程基准 **MLE-bench Lite 上拿到 90.3 分**，比第二名 89.2 高 1.1；另三项第一：OfficeQA Pro 72.2、Harvey LAB 25.0、SpreadsheetBench 2 的 37.1。33 项通用智能体基准里 4 项第一、7 项第二。

真正有意思的是它怎么干活：不是输出一段答案，而是**打开专业软件、看中间结果、回头核验**。CT 切片在 3D Slicer 里重建三维骨骼，发现局部骨性突起就调回原始切面核对；建筑重建在 Blender 里搭完，把渲染预览和参考照片并排比比例和灯光；鄱阳湖水域分析在 QGIS 里导出变化地图和面积表。交付物都是**能再打开、能继续改**的 .blend / .qgis / CAD 文件。

价格策略很激进：即日起至 12 月 9 日为对标模型 GLM 5.3 Flash 的 1%，12 月 10 日起恢复 10%。权重已在 HF 与 ModelScope 开放，技术报告同期放出。

> ⚡ 跟你："交付可编辑工程文件"而不是交付截图——这条对你直接可用。你做创意项目时，agent 该交出可改的源码和矢量文件，而不是一张它自己满意的图。

### C2 · CMU 盯上一个诡异现象：AI 读懂了，却选错了动作

卡内基梅隆的研究团队研究了一类在客服系统里很常见的失败：用户要改订单地址，模型把身份、订单状态、地址格式每一项事实判断都做对了，最后却去调用一个完全不相关的工具，或者干脆什么都不做。

他们给这类问题起名 **System One 模型**——理解层和决策层脱节。这不是"读题读错"，是"读懂了却选错"。传统评测几乎抓不到它，因为最终答案的文字可能还挺通顺，只有动作序列是错的。

> ⚡ 跟你：你验收 agent 时最容易只看"结果长得对不对"。加一条检查：它调了哪些工具、顺序对不对。错误经常藏在动作里，不在文案里。
