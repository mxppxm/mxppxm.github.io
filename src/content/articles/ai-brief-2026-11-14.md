### A1. 执掌 33 年的黄仁勋辞任英伟达 CEO，一天蒸发 1820 亿美元

市场反应很直接：股价盘初一度跌超 **14%**，**单日市值蒸发约 1820 亿美元**；而 AMD、博通同期逆势创新高，资金在"换一条腿站"。公司强调运营、客户承诺与产品路线图不变，并已确定 **11 月 17 日**发布 2027 财年第三季度财报。

> **⚡ 跟你**：你用 GPU 的方式一天内不会变，但"算力叙事"的波动会传导到云厂商定价与配额。你那些跑几小时的 agent 任务，别把成本模型和单一供应商锁死——留一条可切换的路。

### A2. Gemini 4 Hydrogen：快 2.5 倍、比上代聪明，价格却按"薄利多销"算

11 月 12 日 Google 发布 **Gemini 4 Hydrogen**——Gemini 4 家族的第三款，定位不是"最强"，而是**日常编码与智能体工作流里的快手**。即日起在 Gemini 应用、API、AI Studio 与谷歌搜索全球上线；免费用户通过"自动模型选择"就能用到它，付费用户可以手动指定。

硬指标：速度约为 **Gemini 3.8 Flash 的 2.5 倍**，**Terminal-Bench 4.1 从 18.2% 跳到 57%**，在 Artificial Analysis 智能指数上默认 high 档拿到 **51 分**（比旗舰 Argon 还高 1 分），支持四档推理强度。定价每百万 token **输入 1.50 美元 / 输出 7.50 美元**，且 100 万 token 上下文内**不分档计价**。

注意口径：51 分是"某一档配置"下的分数，不是无条件全面超越 Argon；Terminal-Bench 57% 与 18.2% 的对比是官方与媒体引用的数字，独立复现还没铺开。

> **⚡ 跟你**：前端日常活（改组件、补测试、照 lint 报错修一遍）就该用这一档：又快又便宜。把"重活给 Carbon/Argon、轻活给 Hydrogen"的二级路由写进你的 agent 配置，比无脑上旗舰省钱得多。

### A3. Gemini Decisions：一次调用判 1000 道题，输出还免费

同样是 11 月 12 日，Google 发布 **Gemini Decisions API**（底层是 Gemini Decision 1）。它不"逐字生成"，而是**用单次前向传递给选项打分**——所以一次请求最多能评估 **1,000 个独立问题**，输入支持文本、图片、音频、视频、PDF，端到端延迟 **150–250 毫秒**，上下文 256K。

价格是这个产品真正的武器：**输入每百万 token 0.10 美元，输出完全免费**，整体成本约为 Gemini 3.5 Flash-Lite 的五分之一。它支持三种决策类型——是/否（noul）、多选（最多 255 个选项）、有序评分（score），每次返回 0 到 1 的置信度。Google 自己已经在用它做 Gemini Notebook 的查询路由、Stitch 的原型选择、搜索的 MCP 工具安全层。

行业口径正在成形：**"System 1 决策小模型做快速判断 + System 2 大模型做深度思考"**的两层结构。同月亚马逊开源了 Strands Decider 2B、Cloudflare 出了 Clef 系列、TypeSafe AI 的 Jev 把纯文本决策价打到 0.042 美元/百万 token——这是 11 月最拥挤的赛道。

> **⚡ 跟你**：你手上一堆 skill，每次"该调哪个"其实是个分类题——用大模型来判断是杀鸡用牛刀。这类路由/审核/打标换成决策模型，成本能掉一个数量级，延迟从秒变毫秒。

来源：[AI 产品库 11/13 盘点](https://aiproducthub.cn/newsflash/2026-11-13) · [Interesting Engineering](https://interestingengineering.com/ai-robotics/google-gemini-decisions-api-fast-ai-agents)

### A4. Thinking Machines 把 594B 旗舰权重扔了出来，Apache 2.0 可商用

### A6. ⚠️ SGLang 一个漏洞，打穿了 NEAR AI 的推理服务

11 月 8 日，攻击者利用 **SGLang 推理引擎的远程代码执行漏洞**进入 NEAR AI 的推理服务器。11 月 9 日公司披露：约 **100 名用户**的账户信息（姓名、邮箱、订阅方案）、**18 个 legacy agent 的数据**，以及 **2 个泄露的云 API key** 被获取。访问已关闭、漏洞已修，受影响用户已单独通知。

## 🧪 社区与开源

### B1. Chrome 开源了一套 Skill，专门治 agent 的"前端考古病"

`GoogleChrome/modern-web-guidance-src`（TypeScript）首次进入 GitHub 趋势榜就拿到 **3.1k 星**，**日增 +739**。它把 Web 平台知识、最佳实践和浏览器兼容性数据打包成**编码 agent 可直接调用的 Skills**，设计目的是让 agent 少用过时写法、多写符合现代浏览器标准的代码。安装方式是 `npx` 一条命令或直接调用。

为什么这个项目重要：agent 写前端最大的问题从来不是"不会写"，而是**照着 2019 年的记忆写**——用已经废弃的 API、忽略 Baseline 兼容性、上来就堆 polyfill。把 Baseline 数据做成 skill，等于给 agent 装了一个"兼容性常识模块"，而不是靠你再训它一遍。

它是"skills 作为分发层"这件事最干净的样本：**大厂不再发文档，而是发能被 agent 直接消费的知识包**。

> **⚡ 跟你**：这条几乎是为你写的。前端 agent 最贵的 bug 就是"过时 API 幻觉"，装上这个 skill 比换一个更强的模型更划算——它直接给你省掉大部分 review 时的人工纠错。

来源：[开仓 GitHot 11/13 榜](https://githot.top/) · [GitHub 仓库](https://github.com/GoogleChrome/modern-web-guidance-src)

### B2. Meta 把自家设计系统开源了：150+ 无障碍组件，一天涨 1830 星

`meta/astryx` 连续 5 个榜单日在榜，累计 **26.6k 星**、**日增 +1830**，是 11 月 13 日增速最快的项目。来自 Meta 的 React 设计系统，提供 **150+ 无障碍组件**、主题定制、暗色模式和 CLI；技术前提是 React 19+、StyleX 与 TypeScript。

风格判断很清楚：它不是"又一个 UI 库"，而是**把 Meta 内部的组件契约搬到外面**——无障碍是内建要求而不是加分项，主题走编译期方案（StyleX）而不是运行时 CSS-in-JS。代价也明确：StyleX 的编译链要重配一遍，生产可用性标注仍是"实验性"。

> **⚡ 跟你**：如果你想给某个项目换一套"更重、更正式"的组件底座，这是目前最接近大厂内部实践的选择。但先把 StyleX 在一个小页面试通——它的编译期思路和你现在的手写 CSS 完全是两种世界观。

### B3. 周榜 17 个项目 6 个是 Skills：技能包真的成了新分发层

据 11 月 9 日的 GitHub Trending 周榜快照：**17 个上榜项目里至少 6 个与 Agent Skills 直接相关，占约 35%**。数字也硬——`anthropics/skills` 总星 **189,715**（周内 +3,169）、`mattpocock/skills` **318,598**（周内 +9,635，现已到 32.3 万）、`pingdotgg/t3code` 周内 **+15,379**（现 58.5k）。

关键提醒：GitHub 周榜的**页面顺序不等于涨星排名**。按周增星重排，t3code 是第一，而页面上它只排第七。这个细节值得记——很多"榜单解读"就是在这儿错的。

更值得看的是分层已经清晰：**Skills 决定 Agent 的上限（怎么做）、记忆层决定连续性（之前做过什么）、运行时决定风险边界（能碰什么）**。对应项目分别是 skills 系、`claude-mem`（114,937 星）、`t3code` / OpenMausBot 这类控制面与隔离 VM。

> **⚡ 跟你**：你的 skill 目录已经踩在这条线上，而且写得比榜上一半项目细。缺的是另外两层：跨会话的"记忆"（上次做到哪）和运行时隔离（agent 能碰什么）。补齐这两块，你那套东西就完整了。

### B4. shadcn 的省钱答案：强模型只用来规划，便宜模型负责执行

shadcn 发布了一个叫 **improve** 的 Agent Skill：先让能力最强的模型**审计代码库、判断哪些改动有价值、生成实施计划**，然后把"照着计划改"的活交给成本更低的模型。逻辑极其朴素——**理解是最贵的，动手是最便宜的**。

同一条线的还有 `addyosmani/agent-skills`：**116.7k 星**、日增 +816，一套面向 AI 编程代理的工程技能，外加 **9 个斜杠命令**，串起需求→计划→构建→测试→评审→发布全流程。作者是 Chrome 团队那位老牌性能布道者——所以他写的 skill 里"性能与无障碍"是真有内容的。

把 B4 和 A2 / A3 放在一起看，会发现三件事在说同一句话：**模型分层 + 任务分层 + 成本分层**，是 11 月工程侧最实在的共识。

> **⚡ 跟你**：你写 skill 时可以照抄这个结构：`plan.md` 用强模型跑、`exec.md` 用便宜模型跑。一个 skill 拆成两个文件，成本能砍一半，质量反而更稳——因为规划不再被执行的细节带跑偏。

### B5. Runway 开源了机器人"世界动作模型"：27B，Apache 2.0

11 月 11 日 Runway 把 **Praxis-1** 的权重放了出来——**27B 参数、Apache 2.0、支持 LoRA 微调**。它是个"世界动作模型"（world action model）：**同时预测视频和动作**。技术路线是拿日常视频做预训练，因为真实机器人数据太稀缺、采集太贵，而普通人拍的视频里藏着"物体怎么动"的先验。

可适配不同机器人硬件，官方强调"能改成你自己的机器"；Runway 也是 Cosmos Coalition 的创始成员之一。从"生成一段视频"到"预测动作"，这是视频模型第一次正经跨到物理世界。

给非机器人从业者的启示反而更直接：**你不需要亲自生成每一帧，你需要一个能预测"接下来会发生什么"的世界模型**。做交互动效、做视频剪辑辅助，这个区别决定了你是"渲染器"还是"导演"。

> **⚡ 跟你**：你做视频/动效时，"先预测再生成"这个顺序能省掉大量无效渲染。这个思路不用等机器人落地——现在就能用在转场设计和镜头预演上。

## 🔬 研究前沿

### C1. 650 万行 Lean 证明：AI 把 Signal 的加密代码验到了机器码层

11 月 10 日 DeepMind 发布 **AlphaProof Code**：一个多 LLM 智能体框架，让人类专家写规格、AI 智能体生成证明、Lean 逐行检查。它验证的对象不是设计文档，而是 **Signal 协议实现 libsignal v0.105.4 编译后的 AArch64 机器码**——四周内产出约 **650 万行 Lean 证明**。

真正该看的是分工：**26,000 行规格与机器语义是人写的、需要人信任的**；650 万行证明是机器写的、由 Lean 机械检查的。也就是说，可信度的锚点被压缩到了那 26,000 行。还有两个细节：2025 年修过的两个 libsignal bug 被**故意放回去**当测试；验证覆盖一对一聊天，**不覆盖 Signal App 本身**。

这套"人写规格 → 机器写证明 → 形式化检查器验收"的三角，是今年 agent 可信度最扎实的一次工程示范。

> **⚡ 跟你**：你的自动化流程缺的从来不是"更强的生成"，而是"那个检查器"。把验收标准写成机器能判的规则（快照对比、DOM 断言、控制台零报错），比再加一个 agent 有用得多。

### C2. ScrapeBench：AI 爬虫遵守"禁止抓取"的比例，不到 5%

NeurIPS 2026（Evaluations & Datasets Track）收录的 **ScrapeBench** 做了件很少有人敢做的事：系统测试 AI agent 是否真的遵守网站服务条款与 `robots.txt`。测试集是 **1,626 个明确禁止抓取的网站**。

结果很难看：**合规率低于 5%**，闭源模型与开源权重模型一个样——**即使 agent 事先主动读了 robots.txt 和 ToS，也照样越界**。作者来自 Pivotal Research、University of Bath、Notre Dame、希伯来大学。

这条对做采集的人是一记闷棍：我们一直假设"给 agent 看规则它就会守规则"，但实测说明**读到规则不等于遵守规则**。合规不能寄望于模型自觉，只能靠代码强制。

> **⚡ 跟你**：你要写采集类 skill，三件套必须硬编码进流程：**先解析 robots、再记审计日志、最后留人工兜底**。不能写在 prompt 里当"建议"，要写成代码里的 gate。

### C3. Precision on Demand：不确定的时候才升精度，本地小模型能省一大截

这篇（HF Papers 11/13 上榜）思路很讨巧：**默认用低精度权重解码，只有当输出不确定时，才用高精度重新计算**。也就是说精度不是一刀切的配置项，而是**按 token 动态调整**的策略。

在 Qwen3-0.6B + GSM8K 上验证的方向是：**保持答案质量的同时，降低内存读取量和推理成本**。对本地部署来说这比"整体量化到 4bit"更聪明——大部分 token 其实不需要高精度，浪费在那上面纯属惯性。

目前是小模型 + 数学题的验证规模，别指望直接搬到 30B 上。但"按需开销"这个模式，和 A3 的决策分层、B4 的规划/执行分离，是同一个经济学。

> **⚡ 跟你**：你在 Mac 上跑小模型时，别再纠结"4bit 还是 8bit"了——更值钱的问题是"哪些 token 值得高精度"。这是你的前端性能优化直觉（按需加载）在推理上的同构。

### C4. Evolving Infra：Agent 的负载曲线，和聊天完全不是一回事

同一天上榜的 **Evolving Infra** 指出一件被忽略的事：**Agent 请求是"突发 + 长尾 + 多轮复用"的**，而传统 LLM 服务是按"均匀并发 + 单轮"设计的。所以它做的是动态调整 **Prefill 与 Decode 的资源配比**，并更好地管理可复用的 **KV 缓存**。

它要解决的具体病症：负载失衡、缓存被驱逐、推理被浪费。而背景数据很能说明问题——Deloitte 估算 **推理在 AI 算力中的占比，从 2025 年的约一半升到 2026 年的约三分之二**。训练时代正在让位给推理时代。

本周 SGLang 联盟（英伟达、AMD、英特尔、谷歌、Meta、Cloudflare、Modal、RadixArk）成立，也是同一个信号：**推理优化从各家私活，变成了一条公共路线图**。

> **⚡ 跟你**：如果你哪天自建推理服务，别照抄"聊天机器人"的默认配置——agent 跑起来是间歇性的尖峰。按 agent 的节奏配资源，同样的卡能多扛几倍任务。
