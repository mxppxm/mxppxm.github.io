先给你看一个我在本机量出来的东西，它一句话就解释了为什么"我明明统一了明度，页面还是脏"。

七种色相，`hsl(H 90% 50%)`，同样的 `l=50%`。把它们的色值丢进 OKLab 换算，看到的感知亮度是这样：**黄 0.931、青 0.871、绿 0.833、橙 0.714、红 0.606、紫 0.568、蓝 0.441**。同样写 50%，黄的感知亮度是蓝的两倍还多。HSL 的 L 是"往 RGB 立方体里掺了多少白或黑"，它跟眼睛一点关系都没有 —— 你调的是一个几何量，不是亮度。

它在你熟悉的场景里长这样：品牌蓝 `#2563eb`，你要做 hover 态、禁用态、卡片底、浅提示条、正文链接。手往 HSL 的 L 上拖，92 / 84 / 76……一格一格往下走。屏幕上看不出问题 —— 每档确实比上一档深。但你真正在做的事，是把十一个色值排进一条**斜率不定的曲线**里。

![一条从纸白到墨蓝的十二级蓝色阶梯斜向铺在米白纸面上](https://mxppxm.github.io/images/aesthetic-refill-2026-11-23.jpg)

## 量第二条：等步的 HSL 阶梯，跳感并不相等

拿黄色试最狠，因为它的明度天花板离白最近。`hsl(45 95% L)`，L 从 92% 一路走到 12%，每步 8%。

把它换算成 OKLab 的 L，相邻两档的**跳感**是这样的：84→76 只降 **0.029**，而 20→12 一口气降 **0.121**，**差 5.5 倍**。顶上五格（92 → 52）加起来才走了 0.13，底下五格走了 0.53。也就是说你那条"十级黄"，上半截是一块几乎察觉不到差异的糊，下半截是三下闷棍。

反过来，把黄色阶的明度换成眼睛的刻度 —— OKLCH 的 L 从 0.97 均匀走到 0.25 —— 每一格看起来才真的"往下走了一格"。

## 处方：三条规则，和一条能直接抄的表

**一、L 梯子不要等分，浅端要更密。** 我用同样一个商标蓝 `#2563eb`（`oklch(54.6% 0.215 262.9)`）重排了 12 步：浅端从 0.975 起跳，每档只降 **0.030**；中段每档降 **0.080**。为什么不等分？因为**对比度是比值，不是差值**：0.03 的 L 差在纸白附近已经能给出 1.09:1 的分离度，而中段要 0.08 才给到 1.41:1。

**二、chroma 走抛物线，峰值在 L≈0.62。** 纯色只有一个位置最饱和，往两头走必然掉。（这也是 HSL 阶梯真正塌掉的地方：混白 90% 之后，那个蓝的 chroma 从 0.215 掉到 **0.020**，少了 91% —— 五档浅蓝看着都像同一个灰，原因就在这里。）

**三、H 锁死，漂移不要超过 ±2°。** 这条是品味问题也是纪律问题，下面有个反面教材。

按 OKLCH 重排的 12 步（H 固定 262.9°，L 从 0.975 到 0.245，相邻对比度 1.09 → 1.41）：

```css
--c1:  oklch(97.5% 0.012 262.9);  /* #f3f7ff */
--c2:  oklch(94.5% 0.026 262.9);  /* #e4edff */
--c3:  oklch(90.5% 0.046 262.9);  /* #d0e0ff */
--c4:  oklch(85.5% 0.071 262.9);  /* #b7d0ff */
--c5:  oklch(79.5% 0.103 262.9);  /* #99bcff */
--c6:  oklch(72.5% 0.142 262.9);  /* #76a4ff */
--c7:  oklch(64.5% 0.189 262.9);  /* #4d87ff */
--c8:  oklch(56.5% 0.213 262.9);  /* #2c6af0 */
--c9:  oklch(48.5% 0.201 262.9);  /* #1952ce */
--c10: oklch(40.5% 0.179 262.9);  /* #0c3ca7 */
--c11: oklch(32.5% 0.146 262.9);  /* #052a7d */
--c12: oklch(24.5% 0.104 262.9);  /* #041a51 */
```

顺序就是从"背景"到"正文"。想换色相，只改最后那个角度，L 和 C 一列不动。

## 两个色板：一个按"用途"切，一个按"刻度"切

**Radix Colors · 12 步，每步有分工。** 它不按 50–900 那种"纯度梯子"排，而是**按用途**切 12 步：1–2 页面与卡片底、3–5 组件常态 / hover / 按下、6–8 边框与聚焦环、9 是唯一的"纯色"（整个色阶里 chroma 最高的一步）、11–12 两级正文。最硬的一条写在文档里：**11 步和 12 步保证在同色阶第 2 步的背景上达到 APCA Lc 60 与 Lc 90**。这套阶梯不只是"好看地渐深"，它把可读性写成了色板合同。

你该偷的是这个思路：把"我用几档"换成"我有几种活"。多数项目的色板 50 到 950 全部存在、实际只用三档；Radix 反过来 —— 每一档只有一个用途，跳档本身就是语义。C 位只有一个，这也顺手治好了"到处是主色"。

**Tailwind CSS v4 · 11 步 oklch，但它是手调的。** v4 起整个默认色板改成 `oklch()` 定义，可以直接从 `theme.css` 读到原始数值。把 blue 拎出来算 L 阶梯，会读到两个反常识：

- **它也不是等 L 阶梯** —— 最小一步 3.8，最大 10.2（400 那一步），差 2.7 倍。400 故意放大，让 mid-tone 之间能拉开。
- **它的色相一路在漂** —— 50 是 254.6°，到 950 变成 267.9°，**漂了 13.3°**，深色端明显偏紫。这不是 bug，暗部往紫偏会让深色更"沉"，很多印刷色卡都这么干；但它跟上面说的"H 锁死"是两条路。

顺手一个硬数据：**blue-500 在白底上只有 3.76:1**，AA 正文（4.5:1）不过；**blue-600 是 5.25:1** 才过。链接色别落在 500。

## 工具与素材：三个能立刻上手的色阶机器

- **Radix Colors 自定义色板生成器**（[radix-ui.com/colors/custom](https://radix-ui.com/colors/custom)）：给一个色相，直接吐 12 步、带 P3 变体和暗色版，而且按用途命名。先有分工，再有颜色。
- **oklch.com**（[oklch.com](https://oklch.com)）：只管 OKLCH 的取色器，L / C / H 三个滑块，超出 sRGB 色域当场提示，右侧同时给 `oklch()`、hex、P3。用法建议：先把 H 锁住不再动，然后只拖 L —— 拖出来的每一档跳感都是匀的。
- **color.js 的 Picker**（[colorjs.io/apps/picker](https://colorjs.io/apps/picker/)）：W3C CSS Color 4 的参考实现之一，并排看同一颜色在 HSL / OKLCH / Lab 里的三个坐标，判断"这一档到底偏了多少"时读数字比盯屏幕可靠。

> **一句判断**：**"色阶"和"配色"是两件事。** 配色是选几个色相，色阶是给一个色相排班。前者靠品味，后者靠算术 —— 而多数看起来"不高级"的界面，问题都不在配色，在色阶没有排班表。

## 🎯 今天动手（10 分钟）

1. **量两档。** 挑品牌色的两档"浅"（背景和卡片底），DevTools 里切到 oklch 看 L 差多少。差 < 0.03 基本就是糊的。
2. **把最浅那档推下去。** 让最浅的 L 落在 0.97 附近、次浅落在 0.94 —— 只降这一点点，卡片就能"浮"起 1.09:1 的分离度，肉眼刚好够。
3. **顺手验正文。** 链接色和白底算对比度：过不了 4.5:1 就往下挪一档（参考 Tailwind：500 不过、600 过）。
4. **锁住 H。** 把整套阶梯的色相角度抄齐，之后只改 L 和 C。以后新增的状态色都从这 12 格里取，不再现调。
