### A2 Anthropic 让你删掉「仔细思考」：越催越慢，质量还不涨

Anthropic 公开建议：从 Claude Opus 5.5 的提示词里**删掉「努力思考」「仔细想想」这类话**。理由是 Opus 5.5 已是 Pro / Max / Ultra / Team 套餐的默认模型，而很多用户还在沿用旧世代的提示词习惯，**这些多余指令反而拖慢了它**。官方称测试中回复启动更快，质量没有可测的下降。

它还给了一条更具体的建议：**默认用 Medium 档**，表现已经和上一代的 High 档相当。换句话说，思考预算这件事现在是模型自己在管，你手上的「催」更像一个过期的加速踏板——踩了只会让引擎空转。

需要留个心眼：这是厂商自测口径，没有公布延迟的具体数值和评测集；而且结论只对 Opus 5.5 这一代成立。**把「别催」当通用规则套到小模型上，大概率掉质量**——小模型还是需要你给结构。

> **⚡ 跟你**：你过去两年攒的那批 prompt 模板该做一次体检了。挑三个最常用的跑 A/B：删掉「仔细思考」vs 保留，看延迟和返工率，别凭感觉。

### A3 DeepSeek 把 App 拆成零件卖：搜索千次 5 元，官方说能 1:1 复刻

11 月 13 日晚，DeepSeek 开放**全家桶应用 API**：在原有 API 里开启对应参数，就能拿到深度思考搜索、文件输入、阅读链接等对话功能；语音及相关底层能力（OCR、ASR、TTS）也开放为独立接口，可单独调用或自由组合。官方那句话很直白——开发者甚至能**1:1 复刻出完整的 DeepSeek App**。

价格口径已经流出来了：Search 与 Fetch **每千次各 5 元**，文件解析**每千页 1.5 元**，TTS 万字符刊例价 3 元；深度思考搜索单条消息最多约 **20 次**工具调用、只读前 10 个链接。技术上最关键的一点是：**工具调用与上下文拼接由服务端完成**，你不用再自己搭检索、抓取、拼提示词那一整套胶水。

边界也要说清：这套能力目前**只绑在 `deepseek-flash`（V4.1-Flash）**一个模型上，不是一个新模型也不是统一端点；另有开发者已放出 MIT 协议的教程仓库，给了 14 个可运行 demo，从联网搜索到 TTS 都有。

> **⚡ 跟你**：你之前为了给 agent 加「联网查资料」写的那套抓取 + 清洗 + 塞上下文的胶水代码，现在可以用一个参数换掉。省下来的时间正好去做真正值钱的那层：结果怎么呈现给人看。

来源：[DeepSeek API 文档 · 11/13](https://api-docs.deepseek.com/zh-cn/news/news261113) · [Cocoloop 价格核验](https://news.cocoloop.cn/2026/11/deepseek-app-api-search-fetch)

### A5 ⚠️ Cursor 复盘安全事件：一个恶意扩展，最长的一根链条穿透了训练数据

Cursor 公布了完整调查：攻击者利用 **Fireworks 暴露的访问密钥**，读取了用于模型训练的 **coding agent trace**；恶意 **Claude Code 扩展**波及最多 **5,000 名用户**，少于 **0.01%** 客户的 API 凭证被暴露。

这条链之所以值得逐段看，是因为它把三个平时分开评估的风险串成了一条线：第三方推理服务商的密钥管理 → 训练数据里的 agent trace（里面很可能就有你的代码、文件路径和对话上下文）→ 你亲手装的编辑器扩展。任何一环松，后面两环的防护都白做。

背景也别忘了：Wiz 的「黑色十月」报告显示，10 月有**九个 AI 开发者平台接连披露安全事件**。这不是偶发，是这个品类的结构性风险。

> **⚡ 跟你**：三件事今天就能做：翻一遍装过的 Claude Code / Cursor 扩展来源；把生产环境的 key 从 agent 能读到的 `.env` 里挪走；确认你没把含内部代码的 trace 上传给第三方做训练。

来源：[AIHOT 日报 · 11/15（转 Cursor Blog 一手）](https://aihot.news/daily)

### A6 Meta Muse Ember：单价和 Luna 一样，账单贵四倍

Meta 11 月 9 日发布小模型线的 **Muse Ember**，定价**每百万 token 输入 0.10 美元、输出 0.50 美元**——与 GPT-6 Luna、Claude Haiku 5.5 同价。按单价看，这是一张很有攻击性的价目表。

独立评测站 Spring Prompt 在四组业务基准上的结论不太一样：综合分与 Luna 相邻（它自己的榜上第 10 / 35），**问卷分析明显领先**，但**销售文案和 deck 落后**；更关键的一句是——「因为默认按最大推理努力思考，每个任务的成本最多贵 **4 倍**」。

这就是标价与账单的经典分歧：你按 token 付费，成本却由「它想了多少 token」决定。**两边的说法都不假**——官方比的是单价，评测比的是单任务成本。选型时该看后者。

> **⚡ 跟你**：你如果要给创意工具接一个「便宜档」模型跑批（比如一次生成 20 套配色文案），先测单任务成本而不是单价——默认最大推理努力的小模型，能在账单上把你打醒。

## 🧪 社区与开源

### B1 单日 +1,041 星：有人把「Office 内核」做成了可以塞进 AI 产品里的 SDK

`dream-num/univer` 今日新增 **1,041 星**、累计 **25,346 星**（TypeScript），拿下今日 GitHub 趋势第一。它的自我定位很清楚：**Univer Office SDK**——把编辑、计算、协作和文件处理嵌进同时面向人和 AI 智能体的产品，跑在一个可扩展的开源内核上。

为什么是今天涨？因为 agent 现在最缺的不是「会算」，是**「算完存在哪」**。模型能给你一张表，但它没法替你维护单元格历史、公式依赖、多人协作状态——这些是 Office 内核几十年的活。把这块抽象成 SDK，等于给 AI 产品补上了「可编辑的持久化界面」。

这类项目通常不酷，但一旦成为底座就很难被替换。它今天冲到第一，说明有一批做 AI 应用的人同时撞上了同一面墙。

> **⚡ 跟你**：你要做的「AI 生成 → 人改 → 再回喂给 AI」闭环，前端侧最缺的正是这种文档内核。自己写表格/富文本编辑器是纯浪费，接一个可嵌入内核，把精力留给你自己的差异点。

来源：[GitHub 趋势解读 · 11/16](https://gtdaily.news/zh/github/)

### B2 Google 在同一天补了 agent 的两块短板：看得见运行时，和懂规范

`ChromeDevTools/chrome-devtools-mcp` 累计 **56,721 星**，今日 **+718**——一句话就是「给编码智能体的 Chrome DevTools」。同一天 `GoogleChrome/modern-web-guidance-src` 拿到今日**涨幅第一**：**+1,220 星**，累计 6,832 星，功能是「帮编码智能体遵循最新的 Web 最佳实践」。

这两件事拼起来看才有意思：一个让 agent **看见运行时**（控制台报错、网络请求、DOM 状态），一个让 agent **知道规范**（哪些 API 已废弃、新特性怎么用）。而这两块恰好是前端最「隐性」的知识——过去只能靠人在浏览器里手动查、口口相传。

代价也真实：MCP 接得越多，上下文越贵。OpenRouter 之前实测过 GitHub MCP、`gh` CLI 和技能三种接入方式在同一个任务上的上下文成本差异，结论是**工具越多越要算账**，不是越全能越好。

> **⚡ 跟你**：这是今天最该马上试的一条。接上 chrome-devtools-mcp，让 agent 自己开页面、读控制台、点按钮验证——你那套「改完 CSS 靠肉眼猜」的流程可以直接退休。

来源：[GitHub 趋势解读 · 11/16](https://gtdaily.news/zh/github/) · [30Tool · MCP 上下文成本实测](https://www.30aitool.com/daily/)

### B3 阿里把内部代码评审工具开源：51,810 星，规则兜底 + 模型解释

`alibaba/open-code-review` 累计 **51,810 星**、今日 **+688**（Go 语言）。官方描述是「经阿里巴巴规模验证的快速、安全代码评审工具」，架构上做了个混合：**确定性流水线 + LLM 智能体**，逐行给出精准评论，内置 **NPE、线程安全、XSS、SQL 注入**等多语言规则，兼容 OpenAI 与 Anthropic 接口。

这个架构选择值得抄：纯 LLM 评审会漏确定性问题（空指针、注入这类有明确判据的），纯规则引擎又不懂意图、给不出解释。混合起来就是——**规则负责不漏，模型负责说人话**。

还有一个隐性价值：它内置的那份规则清单，本身就是一份「前端最容易漏什么」的检查表。你把它当工具用，顺便也就把清单记住了。

> **⚡ 跟你**：你的 PR 流程如果有 agent 参与评审，别只给它「帮我看看代码」——把确定性规则（XSS、注入、状态竞态）列成硬判据交给它，模型只负责解释和给改法，误报会少一半。

来源：[GitHub 趋势解读 · 11/16](https://gtdaily.news/zh/github/)

### B4 一个人把 Qwen3.8-27B 改成了掩码扩散模型，权重和代码全公开

一位独立开发者把 **Qwen3.8-27B** 改造为**掩码扩散语言模型**，权重与代码全部公开。这件事的分量要看底座：Qwen3.8-27B 在 Hugging Face 本周趋势榜上是 **6.55M 下载 / 20.1k like**，属于当前最被实际部署的那一档开源模型。

老实说：这是个人实验，没有公开基准，别指望它能替你换掉生产模型。但它证明了一件更有价值的事——**基座够强之后，一个人也能改架构**，不用等大厂给你发一个「扩散版」。

> **⚡ 跟你**：你最烦的「只改一小块但模型把整段重写」的问题，解法可能不在提示词，在架构。这条至少给了你一个可以本地跑起来看的样本。

## 🔬 研究前沿

### C1 最强模型只有 66.7%：AI 能设计蛋白质，却读不懂你自己拍的胶图

OpenAI 在 11 月 6 日发布 **BioBasicsBench**，专门考 AI 分析「日常湿实验数据」的能力：**100 项任务**，材料是凝胶电泳图、菌落培养皿、显微镜影像、仪器读数——都是实验室里最普通、也最脏的那类图。

结果是：即便表现最好的 **GPT-6 Astra**，在最高共同推理档位下平均得分也只有 **66.7%**。这个反差很刺眼——同一个行业里，AI 已经能设计新的蛋白质分子，却看不懂你昨晚跑的那张胶。

原因不神秘：论文里的图是被挑选、被排版、被标注过的；真实实验数据是曝光不均、有划痕、标签手写的。这是所有「AI 进垂直行业」都会撞上的同一堵墙——**不是推理不行，是训练数据里没有脏数据**。

> **⚡ 跟你**：做视觉类功能时同一个道理：demo 用的图都是好看的，用户上传的都是歪的。你的评测集里必须有一半是「用户真实会传的那种烂图」，否则上线当天就翻车。

来源：[DeepTech 深科技 · 11/10](https://www.163.com/dy/article/LBCT37B005119734.html)

### C2 端到端 4-bit 训练跑通了：从预训练一路 4 位到 RL rollout

Thinking Machines Lab 在 11 月 15 日发布技术报告：在 **Inkling 2 Small**（594B 总参数 MoE，11 月 5 日发布）上实现了**端到端 4-bit 训练**——从预训练到 RL rollout，统一使用一套数值配方：**前向 NVFP4 + 反向 MXFP8**。
